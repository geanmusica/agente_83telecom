# Ciclo de aprendizado contínuo

Este ciclo é obrigatório após cada interação, tarefa, atendimento, supervisão ou execução operacional.

## Etapas

1. Revisar o que aconteceu.
2. Identificar se surgiu informação nova.
3. Verificar se a informação é confirmada.
4. Verificar se pode ser reutilizada em outros casos.
5. Classificar o destino correto:
   - `regras/` para limites, permissões e decisões obrigatórias;
   - `procedimentos/` para passo a passo operacional;
   - `conhecimento/` para informações técnicas e boas práticas;
   - `integracoes/` para APIs, autenticação e decisões entre API e navegador;
   - `habilidades/README.md` para atualizar o estado de uma habilidade.
6. Comparar com o conteúdo existente para evitar duplicação ou contradição.
7. Atualizar o arquivo correto no GitHub com um commit objetivo.
8. Se não houver aprendizado permanente, não alterar o repositório.

## Pode ser salvo

- Procedimento confirmado e reutilizável.
- Regra operacional permanente.
- Solução técnica validada.
- Erro recorrente e sua prevenção.
- Mudança confirmada na interface, API ou fluxo.

## Não pode ser salvo

- Senhas, tokens, cookies ou credenciais.
- CPF, telefone, endereço ou dados pessoais desnecessários.
- Nome de cliente, contrato, ocorrência ou OS usados apenas em um caso.
- Datas, promessas e agendamentos temporários.
- Suposições ainda não confirmadas.
- Resultado isolado que não possa ser generalizado.

## Atualização de habilidades

- Marcar `[ ]` quando a habilidade ainda não foi ensinada.
- Marcar `[~]` quando existe procedimento, mas falta teste real.
- Marcar `[x]` somente depois de teste autorizado e resultado validado.

## Regra final

O agente não deve afirmar que aprendeu ou que atualizou o GitHub sem ter realizado a atualização e recebido confirmação da operação.
